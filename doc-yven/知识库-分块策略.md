# 知识库分块策略说明

Yuxi 目前支持 **6 种分块策略**，每种策略针对不同的文档类型和结构特点设计，在切分逻辑、合并方式以及是否启用 RAPTOR/GraphRAG 等方面存在差异。

---

## 1. General（通用分块）

- **适合场景**：大多数普通文档，如说明文档、博客、技术文章等。
- **核心逻辑**：
  - 按配置的分隔符（默认 `\n`）拆分文本，再用 `naive_merge` 按 token 上限（默认 512）合并。
  - 超长 chunk 会触发硬切保护。
- **默认启用 RAPTOR**（自动摘要聚类）和 **GraphRAG**（轻量级图谱抽取）。

---

## 2. QA（问答分块）

- **适合场景**：FAQ、题库、问答手册、客服知识库。
- **核心逻辑**：
  - **优先识别 Q&A 结构**，通过多种方式抽取问答对：
    - Markdown 表格 / Excel / CSV 的两列结构
    - Markdown 标题层级（把标题当问题、正文当回答）
    - 前缀标记（如 `Q:`/`A:`、`问题：`/`回答：`）
  - 每个 chunk 输出为标准格式：`问题：... \t 回答：...`
- **禁用 RAPTOR 和 GraphRAG**。

---

## 3. Book（书籍分块）

- **适合场景**：教材、手册、长章节文档。
- **核心逻辑**：
  - **强化章节标题识别**，自动检测文档中的层级标记（如 `第一章`、`1.1`、`# 标题` 等）。
  - 先移除目录页，将冒号结尾的行识别为小标题。
  - 使用 `hierarchical_merge` 按**层级深度 5** 做树形合并，确保上下文连贯。
- **禁用 RAPTOR 和 GraphRAG**。

---

## 4. Laws（法规分块）

- **适合场景**：法律法规、制度规范、政策文件。
- **核心逻辑**：
  - **专门识别法条结构**，如 `第X条`、`第X章`、`第X节` 等。
  - 使用 `tree_merge` 按**层级深度 3** 组织文本，保持"编 → 章 → 节 → 条"的层级关系。
  - 有**多层超长保护**：先按行合并 → 再按句切分 → 最后硬切，避免单条法规过长导致嵌入失败。
- **禁用 RAPTOR 和 GraphRAG**。

---

## 5. Semantic（语义分块）

- **适合场景**：结构复杂、需要语义连贯性的文档，如论文、报告。
- **核心逻辑**：
  - **利用 Embedding 模型进行语义切分**：基于 Markdown-it 解析文档结构，在标题、表格、列表、代码块、图片等边界处切分。
  - 超长段落会结合嵌入向量做**语义聚类切分**，而非简单按长度硬切。
  - **自动增强标题上下文**：每个 chunk 会携带其所属标题路径（如 `## 一级标题|### 二级标题`）。
- **启用 GraphRAG**，禁用 RAPTOR。

---

## 6. Separator（严格分隔）

- **适合场景**：已有明确分隔符、需要精确切分的文本，如日志、剧本、固定格式数据。
- **核心逻辑**：
  - **命中分隔符即切分**，不做智能合并。
  - 仅当单个片段超过 token 上限时，内部再按长度切分。
  - 与 General 相比，**不会跨分隔符合并内容**，保留原始分段边界。
- **禁用 RAPTOR 和 GraphRAG**。

---

## 快速选择建议

| 策略 | 一句话概括 | 是否推荐默认使用 |
|------|-----------|---------------|
| **General** | 通用兜底，带 RAPTOR + GraphRAG | ✅ 是 |
| **QA** | 专抽问答对，适合 FAQ | 仅限问答类 |
| **Book** | 按章节层级合并，适合教材 | 书籍/手册 |
| **Laws** | 按法条层级切分，超长保护强 | 法规/制度 |
| **Semantic** | 基于 Embedding 做语义切分 | 高质量检索场景 |
| **Separator** | 严格按分隔符切，不跨段合并 | 有固定分隔符时 |

> **提示**：如果不确定文档适合哪种策略，**General 是最佳默认选项**。
