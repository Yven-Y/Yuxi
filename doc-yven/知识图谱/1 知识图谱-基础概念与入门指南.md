# 知识图谱基础概念与入门指南

> 整理日期：2026-05-28
> 适用对象：知识图谱初学者
> 目标：建立对知识图谱的系统性认知，了解核心概念与技术架构

---

## 一、什么是知识图谱

### 1.1 定义

**知识图谱（Knowledge Graph, KG）** 是一种用图结构来组织和表示知识的语义网络。它由**节点**（实体、概念）和**边**（关系）组成，能够形式化地描述现实世界中事物及其相互关系。

知识图谱的核心思想是：将知识表示为 **<头实体, 关系, 尾实体>** 的三元组形式，即 **(Subject, Predicate, Object)**，简称 **SPO 三元组**。

### 1.2 发展历史

| 时间 | 里程碑 |
|------|--------|
| 2012年 | Google 正式提出 Knowledge Graph，用于增强搜索引擎 |
| 2013年 | 百度推出"知心"知识图谱 |
| 2016年 | 知识图谱在智能问答、推荐系统中广泛应用 |
| 2020年 | 知识图谱与深度学习深度融合，GNN 成为研究热点 |
| 2023年 | 大模型时代来临，GraphRAG 等知识图谱增强 LLM 技术兴起 |
| 2025-2026 | 知识图谱与大模型融合成为主流方向，LightRAG、GraphRAG 等框架普及 |

### 1.3 知识图谱 vs 传统数据库

| 维度 | 关系型数据库 | 知识图谱 |
|------|-------------|---------|
| 数据模型 | 表格（行/列） | 图（节点/边） |
| 关系表达 | 外键关联，需 JOIN 查询 | 直接关系，天然表达关联 |
| 查询方式 | SQL | Cypher/Gremlin/SPARQL |
| 语义能力 | 弱 | 强，支持推理 |
| 适用场景 | 结构化事务数据 | 复杂关系网络 |

## 二、核心概念

### 2.1 实体（Entity）

实体是知识图谱中的基本元素，代表现实世界中的对象或概念。

- **具体实体**：如"北京"、"张三"、"清华大学"
- **抽象实体**：如"人工智能"、"机器学习"、" capitalism"

每个实体通常具有：
- **唯一标识符**（URI/IRI）
- **类型/类别**（如：城市、人物、学校）
- **属性**（如：人口、出生日期、地址）

### 2.2 关系（Relation）

关系描述实体之间的语义关联。

常见关系类型：
- **层级关系**：is-a（是一种）、part-of（部分 of）
- **空间关系**：located-in（位于）、near（附近）
- **时间关系**：before（之前）、after（之后）
- **社会关系**：friend-of（朋友）、employed-by（受雇于）
- **因果关系**：cause（导致）、result-in（产生）

### 2.3 属性（Attribute）

属性用于描述实体的特征信息。

示例：
```
实体：张三
属性：
  - 出生日期：1990-01-01
  - 国籍：中国
  - 职业：工程师
```

### 2.4 本体（Ontology）

本体是对特定领域知识的形式化、显式化描述，定义了：
- **概念/类**（Classes）：领域中的核心类别
- **属性**（Properties）：概念的特征
- **关系**（Relations）：概念之间的关联
- **约束**（Constraints）：规则和限制

本体是知识图谱的"骨架"，决定了图谱能表达什么知识。

### 2.5 三元组（Triple）

三元组是知识图谱的最小知识单元：

```
(头实体, 关系, 尾实体)  →  (h, r, t)

示例：
(张三, 就职于, 阿里巴巴)
(阿里巴巴, 总部位于, 杭州)
(杭州, 属于, 浙江省)
```

多个三元组连接形成**知识网络**：
```
张三 --就职于--> 阿里巴巴 --总部位于--> 杭州 --属于--> 浙江省
  |                                              |
  --毕业于--> 清华大学 <--位于-- 北京 <--首都-- 中国
```

## 三、技术架构

知识图谱系统通常分为四层架构：

```
┌─────────────────────────────────────────┐
│           应用层 (Application)            │
│  智能搜索 | 智能问答 | 推荐系统 | 决策支持  │
├─────────────────────────────────────────┤
│           算法层 (Algorithm)              │
│  知识推理 | 图计算 | 知识表示学习 | 路径分析 │
├─────────────────────────────────────────┤
│           数据层 (Data)                   │
│  知识存储 | 知识融合 | 知识更新 | 索引管理   │
├─────────────────────────────────────────┤
│           构建层 (Construction)           │
│  知识获取 | 知识抽取 | 知识清洗 | 本体构建   │
└─────────────────────────────────────────┘
```

### 3.1 构建层

负责从多源数据中抽取知识：
- **结构化数据**：数据库、Excel、JSON
- **半结构化数据**：维基百科信息框、HTML 表格
- **非结构化数据**：文本文档、PDF、图片、视频

### 3.2 数据层

负责知识的存储与管理：
- **图数据库**：Neo4j、NebulaGraph、JanusGraph
- **三元组存储**：RDF Store、Virtuoso
- **混合存储**：关系型 + 图存储结合

### 3.3 算法层

提供知识计算能力：
- **知识推理**：基于规则或嵌入的推理
- **图算法**：PageRank、社区发现、最短路径
- **知识表示学习**：TransE、GraphSAGE、GAT

### 3.4 应用层

面向用户的智能应用：
- **智能搜索**：理解查询意图，返回结构化答案
- **智能问答**：基于图谱的自然语言问答
- **推荐系统**：利用关系路径进行推荐
- **风控系统**：识别欺诈网络的关联模式

## 四、知识图谱的类型

### 4.1 按领域划分

| 类型 | 代表 | 特点 |
|------|------|------|
| **通用知识图谱** | Google KG、Wikidata、CN-DBpedia | 覆盖广泛领域，知识量大但精度较低 |
| **领域知识图谱** | 医疗 KG、金融 KG、电商 KG | 专业领域，精度高，知识深度强 |
| **企业知识图谱** | 企业内部知识库、产品图谱 | 面向特定业务，与业务流程深度集成 |

### 4.2 按构建方式划分

| 类型 | 说明 |
|------|------|
| **自顶向下** | 先定义本体，再填充实例（适合领域 KG） |
| **自底向上** | 从数据中自动抽取，再归纳本体（适合通用 KG） |
| **混合方式** | 结合两者优势，先粗略本体，再迭代完善 |

## 五、学习路径建议

### 5.1 入门阶段（1-2 周）

1. 理解知识图谱的基本概念（实体、关系、三元组）
2. 学习 RDF、RDFS、OWL 等知识表示标准
3. 安装 Neo4j，动手创建简单的知识图谱
4. 学习 Cypher 查询语言

### 5.2 进阶阶段（2-4 周）

1. 学习知识抽取技术（NER、关系抽取）
2. 了解知识融合与实体对齐方法
3. 学习知识表示学习（TransE、DistMult）
4. 实践图神经网络（GCN、GAT）

### 5.3 实战阶段（1-2 月）

1. 选择一个领域，构建小型知识图谱
2. 结合大模型实现 GraphRAG
3. 使用 LightRAG/GraphRAG 框架完成项目
4. 探索行业应用场景
