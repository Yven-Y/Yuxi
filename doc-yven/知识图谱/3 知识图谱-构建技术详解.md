## 一、知识图谱构建全流程

知识图谱构建是一个系统工程，通常包含以下 9 大核心步骤：

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 本体构建  │ → │ 知识获取  │ → │ 知识抽取  │ → │ 知识表示  │
│ Ontology │   │ Acquisition│  │ Extraction│  │ Representation│
└──────────┘   └──────────┘   └──────────┘   └──────────┘
                                                  ↓
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 知识更新  │ ← │ 知识推理  │ ← │ 知识融合  │ ← │ 知识存储  │
│ Update   │   │ Reasoning │   │ Fusion    │   │ Storage   │
└──────────┘   └──────────┘   └──────────┘   └──────────┘
```

## 二、本体构建（Ontology Construction）

### 2.1 什么是本体

本体是知识图谱的"骨架"，定义了：
- **类/概念**（Classes）：领域中的核心类别
- **属性**（Datatype Properties）：数据类型的特征
- **关系**（Object Properties）：概念之间的关联
- **层次结构**（Hierarchy）：类的继承关系
- **约束**（Constraints）：领域规则

### 2.2 本体构建方法

| 方法 | 说明 | 适用场景 |
|------|------|---------|
| **手工构建** | 领域专家手动定义 | 高精度、小规模领域 KG |
| **半自动构建** | 专家 + 自动辅助 | 中等规模领域 KG |
| **自动构建** | 从数据/schema 自动学习 | 大规模通用 KG |
| **大模型辅助** | GPT/Claude 辅助生成本体 | 快速原型、敏捷开发 |

### 2.3 本体构建工具

- **Protégé**：斯坦福大学开发的本体编辑器，最主流
- **WebProtégé**：在线协作版本
- **TopBraid Composer**：商业级本体建模工具
- **大模型 + Prompt**：利用 LLM 从文本中自动提取本体 schema

### 2.4 示例：医疗领域本体

```owl
:疾病 rdf:type owl:Class .
:症状 rdf:type owl:Class .
:药物 rdf:type owl:Class .

:疾病 :hasSymptom :症状 .
:疾病 :treatedBy :药物 .

:感冒 rdfs:subClassOf :疾病 .
:发烧 rdfs:subClassOf :症状 .
:布洛芬 rdfs:subClassOf :药物 .
```

## 三、知识获取（Knowledge Acquisition）

### 3.1 数据源分类

| 数据类型 | 示例 | 处理难度 |
|---------|------|---------|
| **结构化数据** | 关系型数据库、Excel、API JSON | 低 |
| **半结构化数据** | 维基百科信息框、HTML 表格、XML | 中 |
| **非结构化数据** | PDF 文档、图片、视频、自然语言文本 | 高 |

### 3.2 结构化数据获取

直接映射到知识图谱：
```python
# 示例：从关系型数据库映射为三元组
# 表：employees(id, name, department_id, manager_id)
# 表：departments(id, name, location)

# 生成的三元组：
# (张三, type, Employee)
# (张三, worksIn, 技术部)
# (张三, reportsTo, 李四)
# (技术部, locatedAt, 北京)
```

### 3.3 半结构化数据获取

维基百科信息框（Infobox）是最典型的半结构化数据源：
- 信息框 = 属性-值对表格
- 可直接映射为实体属性
- DBpedia 项目即基于此构建

### 3.4 非结构化数据获取

需要 NLP 技术进行信息抽取，详见下一节。

## 四、知识抽取（Knowledge Extraction）

知识抽取是从非结构化/半结构化文本中提取结构化知识的过程，包括：
- **实体抽取**（Named Entity Recognition, NER）
- **关系抽取**（Relation Extraction, RE）
- **属性抽取**（Attribute Extraction）
- **事件抽取**（Event Extraction）

### 4.1 实体抽取（NER）

识别文本中的命名实体，并分类。

**常见实体类型**：
- PER（人物）、ORG（组织）、LOC（地点）、GPE（地缘政治实体）
- MISC（杂项）、DATE（日期）、MONEY（金额）

**技术方法**：

| 方法 | 代表模型/工具 | 特点 |
|------|-------------|------|
| 基于规则 | 正则表达式、词典匹配 | 精度高、召回低、维护难 |
| 基于统计 | CRF、HMM | 需要标注数据 |
| 基于深度学习 | BiLSTM-CRF、BERT-NER | 精度高，但计算量大 |
| 基于大模型 | GPT-4、ChatGLM、Llama | 零样本/少样本能力强 |

**主流工具**：
- **spaCy**：工业级 NER 工具
- **Stanford NER**：学术经典
- **Hugging Face Transformers**：BERT 系列 NER
- **HanLP**：中文 NLP 工具包

### 4.2 关系抽取（RE）

识别实体之间的语义关系。

**示例**：
```
文本："马云创立了阿里巴巴"
实体：马云（PER）、阿里巴巴（ORG）
关系：founderOf（创始人）
三元组：(马云, founderOf, 阿里巴巴)
```

**技术方法**：

| 方法 | 说明 |
|------|------|
| **基于模板** | 预定义关系模式，如"X 创立了 Y" |
| **基于监督学习** | 训练分类器判断关系类型 |
| **基于远程监督** | 利用已有 KG 自动标注训练数据 |
| **基于大模型** | 直接让 LLM 抽取关系 |

**经典模型**：
- **PCNN**：分段卷积神经网络
- **BERT-MRC**：阅读理解式关系抽取
- **CasRel**：级联二元标注框架

### 4.3 属性抽取

抽取实体的属性值。

```
文本："阿里巴巴成立于1999年，总部位于杭州"
实体：阿里巴巴
属性：
  - 成立时间：1999年
  - 总部：杭州
```

### 4.4 事件抽取

识别文本中描述的事件及其要素。

```
文本："2023年8月，华为发布了Mate 60手机"
事件类型：产品发布
事件要素：
  - 时间：2023年8月
  - 发布方：华为
  - 产品：Mate 60
```

### 4.5 大模型时代的知识抽取

大模型（LLM）极大地简化了知识抽取流程：

```python
# 使用 LLM 进行端到端知识抽取
prompt = """
从以下文本中提取所有实体和关系，以 JSON 格式返回：
文本：{text}

要求：
1. 实体格式：{"entity": "名称", "type": "类型"}
2. 关系格式：{"head": "头实体", "relation": "关系", "tail": "尾实体"}
"""
```

**优势**：
- 无需训练数据，零样本/少样本即可工作
- 支持开放域关系抽取（不限于预定义关系）
- 可处理复杂、隐含的关系

**劣势**：
- 需要精心设计 Prompt
- 可能存在幻觉（Hallucination）
- 成本较高

## 五、知识融合（Knowledge Fusion）

从多源抽取的知识存在冗余、冲突，需要融合。

### 5.1 实体对齐（Entity Alignment）

识别不同数据源中指代同一现实对象的实体。

```
数据源A："阿里巴巴"（淘宝母公司）
数据源B："Alibaba Group"
数据源C："阿里"
→ 对齐为同一实体
```

**方法**：
- **基于属性相似度**：编辑距离、Jaccard 相似度
- **基于关系相似度**：结构等价性
- **基于嵌入**：TransE 等知识图谱嵌入，计算向量相似度
- **基于大模型**：利用 LLM 判断是否为同一实体

### 5.2 知识合并

将对齐后的实体和关系进行合并，解决冲突。

**冲突类型**：
- **值冲突**：同一属性不同值（如出生日期不一致）
- **关系冲突**：同一对实体标注了不同关系

**解决策略**：
- **投票法**：多源数据多数表决
- **可信度加权**：根据数据源可靠性加权
- **人工审核**：关键数据人工确认

## 六、知识表示（Knowledge Representation）

### 6.1 符号表示

- **RDF（Resource Description Framework）**：W3C 标准
- **RDFS**：RDF Schema，增加类/属性层次
- **OWL（Web Ontology Language）**：表达能力最强的语义网语言

### 6.2 向量表示（知识图谱嵌入）

将实体和关系映射到低维向量空间，便于计算。

| 模型 | 核心思想 | 特点 |
|------|---------|------|
| **TransE** | h + r ≈ t | 简单高效，适合1对1关系 |
| **TransH** | 关系超平面投影 | 解决多对多关系 |
| **TransR** | 关系特定空间 | 更精细的关系建模 |
| **DistMult** | 双线性交互 | 简单有效 |
| **ComplEx** | 复数空间嵌入 | 能建模非对称关系 |
| **RotatE** | 旋转操作 | 建模关系组合 |

## 八、知识推理

基于已有知识推导出新知识。

### 8.1 推理类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **演绎推理** | 从一般到特殊 | 所有人都会死，苏格拉底是人 → 苏格拉底会死 |
| **归纳推理** | 从特殊到一般 | 观察到多个天鹅是白的 → 所有天鹅是白的 |
| **溯因推理** | 从结果推原因 | 草湿了 → 可能下过雨 |
| **类比推理** | 基于相似性 | A 像 B，B 有属性 C → A 可能有 C |

### 8.2 推理方法

- **基于规则**：Datalog、OWL 推理机
- **基于路径**：PTransE、路径排序算法
- **基于嵌入**：TransE 向量运算
- **基于神经网络**：R-GCN、CompGCN
- **基于大模型**：让 LLM 进行常识推理

## 九、知识更新

知识是动态变化的，需要持续更新：

- **增量更新**：只更新变化的部分
- **全量更新**：定期全量重建
- **时效性管理**：为知识添加时间戳和有效期
- **版本管理**：追踪知识的变化历史
